Four calls this file makes that the issue left open, each argued where it appears: (1) the Games scene is the overhead feed full-bleed with the live scene's own bottom-bar language — no side panel; (2) on-cloth markings are white (cue) and slate dashed (object) because accent blue vanishes into blue cloth — accent and alarm live only in the HUD bar; (3) the picker takes row 3, the row that is the mode's own block in every other mode; (4) PLAY and NEXT are one key with two faces (the Replay-key precedent) — a deliberate deviation from the issue's key list, flagged in §5.

2 · Playing a shot — the drill loop on the wall

The overhead feed fills the screen; the bar along the bottom is the only HUD. The split of labor matters for the build: everything on the cloth (grid, ghosts, zones, miss line) is drawn server-side in the display pipeline; everything in the bar is the /games source. The bar is the live scene's plinth wearing games content, so the wall keeps one voice: eyebrow + name left, stat lockups center, and the answer cell on the right where the clock lives during a match.

6 · The phone — a Drills tab

Third tab, same pattern as Match: the table captures, the phone curates. The list is where make % lives per shot (from the journal); the editor is rename / re-zone / delete plus "serve this one." Zones are edited on the same 8×4 grid the TV and the table speak — tap a cell to move the block, size it with a segmented control. Layout and ghosts are not editable here: positions come from the table, always.

7 · Decisions this file takes — iterate here

Taken in v1, arguable: (1) Full-bleed feed + bottom bar, no side panel — the table is the instrument and the live scene already taught this bar's grammar. A side panel was considered and dropped: it shrinks the table to make room for chrome. (2) On-cloth colour code: white = cue's markings, slate dashed = object ball's, alarm red = miss line only. Accent never touches the cloth (blue on blue). (3) Picker on row 3; games verbs wear MATCH blue; capture is a row-3 transient overlay. (4) PLAY/NEXT merged into one two-faced key; RETRY separate because re-serving the same shot and serving another must never be one mispress apart. (5) Ghosts drop at arm; the zone stays lit through the shot. (6) Lag scores every settle, no arming — only the best matters, so noise is free. (7) Phone edits zones on a grid picker but never moves balls or ghosts — the table stays the only positional input device. Not drawn, deliberately: pagination of the picker (two games don't need it), weighted-random serving, party games, any Games-scene appearance of the side-angle camera (judging is overhead; Camo adds nothing here).
